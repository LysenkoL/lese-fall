# LESE-FALL — DETEKTIV-ATELIER

## Окончательное дизайн- и UX-ТЗ v2.0 · 3 ноября 2026

**Статус:** выбранная дизайн-концепция для создания первого рабочего прототипа. Старое `LESE-FALL_Design_System_Mobile_Tablet_v1_FINAL.md` **заменено** этим документом в части визуальной компоновки и навигации. Не является художественным сценарием.

**Единственный источник литературного текста:** `01_text/LESE-FALL_BUCH_1_TEXT_FINAL_v5_1.md`. Файл текста нельзя сокращать, переписывать, переставлять события, добавлять реплики или заменять содержимое на текст из ИИ-макетов. Упоминания «Seite 1–24» в сценарии обозначают **24 сюжетные сцены**, а не физические экранные листы.

**Целевые устройства:** смартфоны Android и планшеты, без отдельного desktop-дизайна. Ориентация телефона преимущественно портретная; планшет поддерживает портрет и альбомную. **Озвучки нет**; ребёнок читает сам, за один или несколько подходов. ## 1. Одно выбранное визуальное направление

### Detektiv-Atelier: «Настоящая книжка, которую ведёт маленький детектив»

- Приоритет — полноценный, легко читаемый литературный текст, а не форма тестирования.
- Книжная композиция: светлые поля, тёплый фон, выразительная, но ненавязчивая иллюстрация, крупный школьный текст, ощущение перелистывания.
- Детективный слой — дозированно: значок Tautropfen-Lupe, небольшие бумажные метки улик, карточка задания как «страничка дела», золотистый свет усиков при успехе.
- Читатель знает мысли гусенички, люди в сюжете их не слышат. Не изображать её разговаривающей с детьми или перемещающей реквизит.
- Визуально использовать **именно существующий фирменный дизайн Leseraupe**. Новые шляпа, лупа и золотистые точки усиков — только аксессуары/эффекты, не редизайн мордочки, тела и цветов.
- Без избыточных записок, полароидов и маркеров: не больше 1–2 детективных декоративных акцентов на одном листе. Текст никогда не лежит на пёстром фоне.

## 2. Шрифты: конкретное решение по Inter из оригинальной Leseraupe

**Решение:** оставить **Inter от Rasmus Andersson, лицензия SIL OFL 1.1**, но включить OpenType-альтернативу одноэтажной строчной `a`, известную как `cv11`. У Inter базовая форма `a` двухэтажная; `cv11` делает её одноэтажной. Строчную `g` проверить в именно установленном комплекте. Это позволяет сохранить узнаваемый шрифт старого приложения, не выдавая детям неподходящую форму буквы `a`.

```css
/* Использовать локально поставляемую проверенную версию Inter.
   Эта настройка применяется ко ВСЕМ читаемым немецким текстам,
   включая цветные слоги, вопросы, ответы и мысли гусенички. */
.story-text, .story-title, .raupe-thought, .task-question,
.task-option, .evidence-text, .reading-controls {
  font-family: "Inter", sans-serif;
  font-feature-settings: "cv11" 1;
}
.story-text { font-size: 20px; line-height: 1.6; font-weight: 400; }
.task-question, .task-option { font-size: 19px; line-height: 1.5; }
```

**Не принимать по названию шрифта на веру.** Перед реализацией проверить `a ä g I l 1 ß ö ü` с `cv11` в браузере и внутри Android-сборки, с красно-синими слогами и при жирном начертании. Если фактический Inter в проекте не содержит `cv11` или его не применяет среда, **только для основного читательского текста** использовать проверенную Andika со стандартной одноэтажной `a`/`g`; UI и логотип могут остаться на Inter. Не пересобирать/не распространять сторонние файлы шрифтов за пределами разрешённого лицензией.

- Смартфон: основной текст 19–20 CSS px, не опускать ниже 18 px из-за плотности сцены; междустрочный интервал ориентировочно 1.55–1.7.
- Планшет: 20–23 CSS px с ограниченной длиной строки примерно 45–65 знаков, а не растяжкой текста от края до края.
- Настройка `Aa` увеличивает текст, но не меняет сюжет и не отключает перелистывание. Текст переносится на дополнительные экранные листы автоматически.
- Не использовать курсив как обязательный способ выделить мысли гусенички: форма букв важнее декоративности. Не делать надписи частью рисунка; текст и слоги — настоящие DOM/нативные символы.

**Слоги:** предрассчитанное и педагогически проверенное разбиение, отдельно от канонического текста. На каждом слове начать с синего, затем красный, синий, красный. Примеры редакторской разметки: `be|geis|tert`, `in|zwi|schen`, `Fens|ter|brett`, `Schnip|sel`, `ver|schwun|den`. CSS не умеет правильно определять слоги самостоятельно; нельзя раскрашивать случайные группы букв. При выключенном `Silbenfarben` исходный текст отображается в точности без разметочных символов. Слоговый режим должен работать и в заданиях, и в доказательствах.

## 3. Критически важно: Android Safe Areas, как НЕ повторить ошибку Leseraupe

**Проблема:** приложение ранее «уезжало» под верхнюю строку системных часов/сети и под нижнюю навигационную панель Android. На Android 15+ при `targetSdk >= 35` действует edge-to-edge, поэтому нельзя считать всю высоту окна безопасной для кнопок и текста.

### Обязательная схема приложения (три слоя + системные поля)

```text
┌──────────────────────────────────┐
│ SYSTEM STATUS AREA               │  ← часы, сеть, камера/вырез
├──────────────────────────────────┤
│ APP HEADER                       │  ← назад, глава, прогресс, настройки
├──────────────────────────────────┤
│ READER PAGE (PAGINATED)          │  ← только доступная безопасная область
│ illustration / story / task      │     один экранный лист; свайп страниц
├──────────────────────────────────┤
│ APP BOTTOM CONTROLS              │  ← назад / лист n из m / дальше
├──────────────────────────────────┤
│ SYSTEM NAVIGATION AREA           │  ← gesture bar / 3 кнопки Android
└──────────────────────────────────┘
```

- Верхняя строка Android и нижняя полоса системной навигации **не содержат интерактивных элементов приложения**. Можно продолжить фоновый цвет под системной областью, но фактические кнопки размещаются только после расчёта safe insets.
- Хедер и нижняя панель — самостоятельные layout-области, не часть перелистываемого текста. Не использовать абсолютное позиционирование `top:0; bottom:0` без отступов.
- Safe insets брать из **реального системного API** (`WindowInsets`) для нативной обёртки. Если приложение WebView/Capacitor, прокинуть достоверные Insets из обёртки в CSS; `env(safe-area-inset-*)` использовать как поддерживаемый источник/fallback, но не считать гарантированно ненулевым на всякой Android WebView. Не суммировать один и тот же inset дважды.
- Учесть вырез камеры, закруглённые углы, жестовую навигацию, старую 3-button navigation, изменение ориентации и размеры от уменьшенных до больших.
- Нельзя фиксировать высоты системных областей как «всегда 24px / 48px»: они зависят от устройства и настроек.

### Рекомендованная модель для HTML/CSS в совместимой WebView

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
<div class="app-shell">
  <header class="app-header">...</header>
  <main class="reader-viewport">...</main>
  <nav class="app-bottom-nav">...</nav>
</div>
```

```css
:root {
  /* Native bridge может задать --native-safe-*; иначе применим env().
     Не добавлять значения ещё раз в header/footer/children! */
  --safe-top: var(--native-safe-top, env(safe-area-inset-top, 0px));
  --safe-bottom: var(--native-safe-bottom, env(safe-area-inset-bottom, 0px));
  --safe-left: var(--native-safe-left, env(safe-area-inset-left, 0px));
  --safe-right: var(--native-safe-right, env(safe-area-inset-right, 0px));
}
html, body, #root { margin: 0; width: 100%; height: 100%; }
.app-shell {
  box-sizing: border-box;
  width: 100%; height: 100dvh;
  display: grid;
  grid-template-rows: auto minmax(0, 1fr) auto;
  padding: var(--safe-top) var(--safe-right) var(--safe-bottom) var(--safe-left);
  background: var(--bg-page);
  overflow: hidden;
}
.app-header, .app-bottom-nav { min-height: 52px; flex-shrink: 0; }
.reader-viewport { min-height: 0; min-width: 0; overflow: hidden; }
.book-sheet { width: 100%; height: 100%; overflow: hidden; }
/* Переполнение не обрезаем и не скроллим: движок добавляет новый ЛИСТ. */
```

Это **архитектурный пример, не слепая инструкция**: если уже применена native `fitsSystemWindows`/Scaffold/inset padding, второй раз `safe-top`/`safe-bottom` в CSS не прибавлять. При Android WebView проверить фактические Insets в запущенном APK, а не только в Chrome DevTools. Если среда использует PWA/TWA без нативного API, применять доступные механизмы браузера и отдельно проверять установленную сборку на телефоне.

### Запреты

- Никакой кнопки `Prüfen`, `Weiter`, стрелок, счётчика жемчужин или `Aa` под системным статус-баром или нижним gesture-bar.
- Никакой имитации системных часов или батареи как части приложения.
- Никакого `100vh` вместе с захардкоженным bottom padding, из-за которого панель уезжает вниз, когда Android показывает/скрывает системную область.
- Не решать баг уменьшением размера шрифта или текста.

## 4. Настоящее книжное перелистывание — НЕ вертикальный скролл

**Выбор пользователя утверждён:** книгу читают с постраничным переходом кнопками и свайпом, как в электронной книге. Режим `ReadingStory` из старого дизайн-ТЗ с `Scroll` полностью отменён.

1. Сюжетная сцена — единица истории и задания. Внутри неё может быть столько экранных листов, сколько потребуется для **ВСЕГО текста** на конкретном устройстве. Например, «Seite 2» сценария может стать физическими листами `2.1`, `2.2`, `2.3` — это не новые сцены и не новый текст.
2. Страница имеет ограниченную высоту **между настоящим хедером и нижней навигацией**. Движок измеряет доступную область и адаптивно распределяет исходные абзацы на целое число листов. Нельзя использовать `line-clamp`, `text-overflow: ellipsis`, обрезающий фиксированный контейнер для содержимого без продолжения.
3. Разрыв предпочтительно по границе абзаца/предложения. Если абзац не помещается — допускается перенос между строками на границе слов с сохранением полного исходного текста и правильной последовательности. Не оставлять одинокий заголовок на листе; не создавать почти пустые листы без причины.
4. Размер шрифта, включение красно-синих слогов, поворот устройства и системный масштаб могут менять количество физических листов. Пересчёт НЕ должен отправлять читателя в начало. Сохранять смысловую позицию по якорю **sceneId + текстовый offset/ID абзаца**, а не только номеру листа.
5. Свайп влево/вправо и кнопки `‹ / ›` работают одинаково. Вертикальной прокрутки книжного текста нет. Выделение текста, связь с доказательством и системный back-gesture не должны случайно переключать листы.
6. В момент входа в сцену доступны только её листы. После последнего листа появляется следующий **отдельный лист `Dein Ermittlerauftrag`**. Назад к прочитанному можно всегда; на следующую **сюжетную сцену** — после завершения задания (включая поддержанное завершение при затруднении).
7. Все открытые ранее сцены доступны через оглавление/книжную навигацию; повторное чтение не даёт новых жемчужин. При закрытии приложения возвращаться к текущему листу по сохранённому текстовому якорю.
8. На телефоне — один лист на весь безопасный reader viewport. Планшет-портрет — один более широкий книжный лист. Планшет-альбомный — **допустим двухстраничный разворот** при достаточной ширине, но с правильным непрерывным порядком чтения; отдельный скролл в левой колонке не нужен.
9. Сохранить минимум 12–16px внутренних безопасных полей по краям текста на смартфоне, с учётом `safe-left/right` и размеров экрана; на планшете — широкие книжные поля. Максимальная длина строки ограничивается.
10. Детективное мыслительное облако занимает место внутри литературной последовательности и может переноситься на следующий лист целиком, если иначе будет разрезано. Реплики гусенички **не дублировать**: один канонический фрагмент текста, оформленный иначе.

**Порядок физических листов в сцене:** один или несколько листов чтения → отдельный лист задания → при необходимости режим доказательства → экран мини-победы → чтение следующей сюжетной сцены. Кнопка «следующая сцена» не появляется активной заранее.

## 5. Экранная композиция Detektiv-Atelier

### Смартфон — лист истории

- Компактная постоянная панель: `←`, `Kapitel X · Szene Y`, настройка `Aa`/`Silbenfarben` (можно объединить в меню, чтобы не перегружать узкий хедер), деликатный прогресс.
- На первом экранном листе сцены — плейсхолдер сюжетной иллюстрации (позже — реальный art asset), название, начало текста; на последующих листах иллюстрация не обязана дублироваться. Возможны одна маленькая сюжетная зарисовка или мысли Leseraupe в рамках естественного хода текста.
- Никакой декоративной «канцелярии», перекрывающей буквы. Подложка текста однотонная и контрастная. Предпочтительны поля настоящего листа, а не десять вложенных карточек.
- Нижняя стабильная навигация: `←` и `→`, обозначение `Лист n из m` / `Blatt n von m` (можно отобразить только там, где уместно), доступность заранее открытых листов.

### Смартфон — лист `Dein Ermittlerauftrag`

- Небольшая смысловая иллюстрация улики **без ответа или спойлера**. Вопрос и варианты занимают основной экранный фокус.
- `Prüfen` активно только после полноценного выбора/сборки комбинации. При длинных вариантах допускается несколько **физических листов задания**, но целостность вопроса и выбора сохраняется; нельзя скрывать варианты под системной панелью.
- `Zur Geschichte` видима и работает без потери выбранного ответа. При возвращении из текста ребёнок вновь попадает в тот же экран задания, а не в начало главы.
- До ошибки `Zeig den Beweis!` не показан как самостоятельная активная кнопка; при желании дать добровольную помощь — отдельный `Tautropfen-Tipp`.

### Планшет

- Портрет — страница с иллюстрацией, текстом и широкими внешними полями. Увеличенный экран не повод делать бесконечно длинные строки.
- Альбомная ориентация — книжный разворот, где иллюстрация может находиться на одном листе, текст — на другом; если текст длинный, появляется следующий разворот без его сокращения. Два внутренних скролла запрещены.
- Задание — отдельный лист/разворот дела, не заставляющий одновременно следить за двумя независимыми прокрутками.

### Иллюстрации и спойлеры

- `before/after` либо локальные слои используются только где сюжет это требует. Например, пустая сцена театра в момент пропажи (сцена 2) **не показана до проверки ответа**; для ложного жёлтого круга (сцена 4) оборот закрыт до уместного раскрытия; звезда+нитка в сцене 16 показываются только после описанного текстом открытия.
- Иллюстрация не подсказывает правильный вариант цветом, размером, стрелкой, мимикой. Нет узнаваемого «правильного» значка у одного ответа.
- В художественном слое имена/подписи размещать отдельно настоящим текстом, а не генерировать буквы внутри картинки.

## 6. Состояния задания, реакции Leseraupe и Schimmer-Perlen

### Машина состояний

`READING → TASK_READY → SELECTING → CHECKING → (SUCCESS | EVIDENCE_MODE)`

`EVIDENCE_MODE → TASK_RETRY → (SUCCESS | MORE_HELP) → ASSISTED_COMPLETION → SUCCESS`.

Реальный переход может быть реализован как несколько компонентов, но **никакой бесконечной цепочки угадываний**: после повторного затруднения доступно смысловое объяснение и завершение сцены.

### A. `Prüfen` — правильный ответ

1. Проверяется вся комбинация целиком (для `PairSelect`, `SequenceSelect` — не первый тап).
2. Гусеничка **меняет эмоцию на радостную**, кончики Leucht-Fühler тихо светятся золотисто. Краткий акцент Tautropfen-Lupe / маленький лучик на связанной с текстом улике.
3. Появляется короткая фраза по смыслу: `Richtig erkannt!`, `Spur entdeckt!` или контекстная реплика из данных сцены. Не заменять книжный текст этой фразой.
4. Подтверждается правильный ответ/следствие, при необходимости открывается `imageAfter`.
5. Появляются заработанные **Schimmer-Perlen**, мягко перемещаются в небольшой счётчик. Не делать громоздкий фейерверк, модальное окно с обязательным ожиданием, вспышки на весь экран или звуки.
6. Показывается активное `Weiterlesen` / переход к следующей сцене; можно перечитать текущую и снова посмотреть её улики.

### B. `Prüfen` — неверный ответ

1. Спокойная реакция: гусеничка задумалась, лупа слегка подсвечивается. Реплика вроде `Hm, schauen wir noch einmal genau hin.` — не `Falsch!` большими красными буквами, без отрицательных баллов.
2. **Только теперь открывается `Zeig den Beweis!`**: короткое проверяемое действие, связанное с исходным предложением (найти предложение/сопоставить факт/прочитать предлог). Сразу правильную фразу или кнопку не подсвечивать.
3. После найденного доказательства первоначальные ответы очищаются для новой осмысленной попытки. Важно: **первая ошибка не отнимает жемчужин**.
4. Если ребёнку снова сложно, предложить `Weitere Hilfe`: контекстную смысловую подсказку. Если и после неё сложно — показать объяснение и дать поддержанно завершить сцену.

### C. Сколько жемчужин

| Исход | Итоговая награда за эту сцену |
|---|---:|
| Верно сразу | **2 Schimmer-Perlen** |
| Первая ошибка → самостоятельно найдено доказательство → верно | **2 Schimmer-Perlen** |
| Завершение после дополнительной смысловой помощи | **1 Schimmer-Perle** |
| Понадобилось раскрыть и объяснить решение | **1 Schimmer-Perle** |

**Правила:**

- Слоговая помощь, настройки шрифта, возврат к тексту, изменение ответа до `Prüfen` не влияют на награду.
- Первая ошибка — не наказание. `Zeig den Beweis!` — продолжение обучения, не штраф.
- За завершённую сцену выдаётся награда **ровно один раз**, даже при повторном чтении или повторном нажатии. Хранить `rewardIssued`/`pearlsAwarded` по `sceneId`.
- Максимум **48 жемчужин за 24 задания** при двух на каждом. Показывать небольшую сумму в UI, не превращая её в соревновательный счётчик. Жемчужины используются в уже знакомом гардеробе Leseraupe (если он подключён к этому приложению), без второй параллельной валюты.
- Детективная история **никогда не блокируется** из-за количества жемчужин. В гардеробе не должно быть обязательной покупки, чтобы дочитать книгу.
- В конце каждой главы можно показывать краткий прогресс: `Kapitel geschafft!` + собранные жемчужины + маленькую позитивную реакцию Leseraupe, без оценок школьного типа.
- В настройках `Bewegung reduzieren` (или системная `prefers-reduced-motion`) отключает переливы/перелёты жемчужин; награда начисляется мгновенно и текстом.
- **Звуков не использовать**, поскольку выбран режим без озвучки и не предусмотрены аудиоэффекты.

### D. Пример экранного сценария мини-победы

```text
[Гусеничка улыбается; усики золотисто светятся]
Spur entdeckt!
„Du hast genau hingesehen!“
                 ✦ ✦   +2 Schimmer-Perlen
[Все заработанные жемчужины: 8]
[↶ Noch einmal lesen]       [Weiterlesen →]
```

Варианты немецких коротких реакций хранятся как **отдельные UI-строки**, а не добавляются в канонический книжный текст. Реакции могут зависеть от сцены; не использовать одну фразу 24 раза подряд.

## 7. Сохранение прогресса и игровая интеграция

Минимальный набор состояния:

```json
{
  "bookId": "der-verschwundene-mond",
  "sceneId": "chapter1-scene2",
  "readingAnchor": {"paragraphId":"p3", "charOffset":24},
  "completedScenes": [],
  "taskDraft": null,
  "settings": {"silbenfarben":false,"fontScale":1.0,"reducedMotion":false},
  "rewardsByScene": {"chapter1-scene1":{"issued":true,"pearls":2}},
  "totalPearls": 2
}
```

- Сохранять атомарно при завершении задания и периодически при смене листа; при аварийном закрытии не терять пройденную сцену и не начислять награду дважды.
- Книжный текст для цветных слогов хранится отдельно от служебных элементов страницы. Проверить механически совпадение исходного канонического текста после удаления представления слоговых spans с оригиналом (включая знаки и последовательность абзацев).
- Перелистывание после изменения размера шрифта/поворота экрана основано на текстовом якоре, не на старом номере физического листа.
- Ранее пройденные сцены доступны повторно; `Prüfen` в повторном просмотре не создаёт новые награды.
- Специальный экран `Schimmer-Perlen` и старый `Raupen-Garderobe` интегрировать с существующей системой старого приложения только после проверки интерфейсов; не дублировать валюту на уровне БД.

## 8. Требуемые компоненты первого прототипа

1. `AppSafeAreaShell`: корректные native/browser insets, отсутствие перекрытий.
2. `ReaderToolbar`: компактная навигация сцены, шрифт `Aa`, `Silbenfarben`, прогресс.
3. `PaginatedBookReader`: программная пагинация полного текста, сохранение якоря, листание кнопками и свайпом, reflow.
4. `SceneIllustration`: оригинальные assets (в прототипе допустимы neutral placeholder) с `before/after` при необходимости.
5. `RaupenThought`: единственное визуальное оформление мысли в её исходном месте в тексте.
6. `InvestigationTask`: `OptionSelect`, `PairSelect`, `SceneSelect`, `SequenceSelect`, `ReferenceSelect` по данным сцены.
7. `EvidenceMode`: `Zeig den Beweis!` только после ошибки, с возвращением к точному тексту.
8. `HintMode`: `Tautropfen-Tipp` (если предусмотрен) и `Weitere Hilfe`, поддержанное завершение.
9. `RewardAnimation` + `PearlWallet`: визуальная реакция + выдача 2/1 жемчужин, защита от дублей.
10. `ChapterCompletion`: мини-итог главы и переход, сохранение.

**Не создавать 12 вариантов макетов:** выбран только `Detektiv-Atelier`. Для первого рабочего UX-прототипа достаточно **трёх эталонных состояний** на телефоне и планшете: лист с текстом/иллюстрацией, лист задания, успех/ошибка с доказательством и жемчужинами. Потом масштабировать шаблон на 6 сцен главы 1 и далее на 24.

## 9. Проверки перед передачей иллюстраций в производство

### Typography QA

- [ ] Фактически используемый Inter с `cv11` показывает одноэтажную `a` и ожидаемую форму `g`, в том числе в немецких словах `Mama`, `Raupe`, `Mädchen`, `Glas`, `gaga`.
- [ ] `I`, `l`, `1`, диакритика и `ß` читаемы в красно-синем и обычном тексте.
- [ ] Все слова в 24 сценах имеют проверенную слоговую разметку, а не случайные цвета букв; исходный текст неизменён.

### Android Safe Area QA

- [ ] На настоящих Android-смартфонах нет пересечения с часами/Wi-Fi/вырезом камеры и нижней полосой жестовой навигации.
- [ ] То же при 3-button navigation, на Android 14/15+, разных `targetSdk`, при смене ориентации, системного масштаба и разрешения.
- [ ] Тестировать минимум небольшую ширину ~360 CSS px, стандартную ~393, большую ~430; планшеты ~768–1024 и ландшафтные сценарии.
- [ ] Нет дубля системных отступов при переходе native → WebView → CSS. Bottom controls доступны пальцем без попадания в системный жест.

### Reader QA

- [ ] Вся сцена `v5.1` представлена на одном/нескольких листах **без пропусков, повторов и троеточий вместо текста**.
- [ ] Нет вертикального скролла или вложенного независимого скролла для книги; есть кнопки и свайп.
- [ ] Не теряется положение после изменения шрифта, слогов, ориентации, перезапуска приложения.
- [ ] Перелистывание не случайно срабатывает при тапах по вариантам, выделении слова, возврате к тексту или системном Back.

### Task/Reward QA

- [ ] `Prüfen` активно только при полном выборе; до проверки ответы визуально равноправны.
- [ ] После ошибки появляется `Zeig den Beweis!`, но не готовое решение; при повторном затруднении есть `Weitere Hilfe` и поддержанное завершение.
- [ ] Правильный ответ сопровождается реакцией гусенички, `+2`/`+1` жемчужинами, возможным `imageAfter`, активной кнопкой `Weiterlesen`.
- [ ] Жемчужины не выдаются повторно, после перезапуска суммарное количество сохраняется.
- [ ] Снижение анимации и полное отсутствие аудио работают корректно.
- [ ] Иллюстрации не раскрывают ответ до текста/проверки (особенно страницы 2, 4, 16).
