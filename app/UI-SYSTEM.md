# UI-система Lese-Fall (v8)

Короткая памятка: где менять общие параметры и как добавлять экраны, чтобы не ломать адаптивность.
Действует для актуальной версии `app/v8.html` → `src/v8/main.ts`. Старые версии (`index.html`, `v7.html`) не затронуты.

## Порядок файлов (импорты в `src/v8/main.ts`)

| № | Файл | Что в нём | Когда трогать |
|---|---|---|---|
| 1 | `src/v8/ui/tokens.css` | только значения: цвета, шрифтовая шкала, отступы, радиусы, тени, размеры кнопок, максимальные ширины, системные поля, слои, длительности | поменять цвет, размер кнопки, шкалу шрифта — **только здесь** |
| 2 | `src/v8/ui/basis.css` | шрифт, сброс, масштаб по устройству, оболочка (шапка · сцена · низ · окна), каркасы видов экранов | поменять поведение на телефоне/планшете, поля, шапку |
| 3 | `src/v8/ui/komponenten.css` | общие детали: кнопки, ярлыки, карточки, облачко гусенички, печать, фото, диалоги | поменять вид детали сразу везде |
| 4 | `src/v8/ansichten.css` | экраны: обложка, вступление, карточка главы, чтение, «крючок», доска, карточка дела | вид конкретного экрана |
| 5 | `src/v8/raetsel.css`, `k3.css`, `k4.css` | общий каркас игры и мини-игры (главы 1–2, 3, 4 + финал), каждая игра — свой блок | вид конкретной игры |
| 6 | `src/v8/effekte.css` | анимации, «момент инструмента», награды; в конце — отключение движения | движение |

Правило направления: файл может опираться только на файлы выше себя. Поздних «исправляющих» слоёв нет — правка делается в блоке, которому правило принадлежит.

## Четыре принципа

1. **Одна базовая величина.** Все размеры интерфейса заданы в `rem`. Планшет — это больший базовый размер, а не другой набор правил. Ступени заданы один раз в начале `basis.css` («Grundgröße je Gerät»):
   - телефон — 16 px;
   - от 600×700 — 18 px;
   - от 900×700 — 19 px;
   - от 1100×760 — 20 px.

   В `px` остаются только волосяные линии, рамки, тени и узоры.
2. **Сцена знает свой размер.** `#buehne` — контейнер (`container: buehne / size`). Всё, что зависит от свободной высоты, считается от сцены в `cqh`/`cqw`, а не от экрана (`dvh` минус «примерная» высота шапки). Смена композиции — через `@container buehne (...)`, а не через размеры конкретных телефонов.
3. **Прокручиваемое не сжимается.** У детей прокручиваемого экрана `flex-shrink: 0`. Если не помещается — экран прокручивается целиком, элементы никогда не наезжают друг на друга. Сетки пишутся как `minmax(0, 1fr)`, иначе длинное слово раздвигает экран.
4. **Системные поля считаются один раз.** `--oben` — в шапке (или у сцены, когда шапки нет), `--unten` — в нижней панели и в окнах, `--links/--rechts` — у `#app`. В экранах и играх их не добавлять.

## Виды экранов (каркасы в `basis.css`)

| Вид | Классы | Телефон | Планшет в портрете | Планшет в альбоме |
|---|---|---|---|---|
| Центр | `.titel .intro .kapk .haken` | колонка по центру | то же, крупнее | то же |
| Чтение | `.blatt` | лист на весь экран | лист на весь экран, строка не длиннее `--mass-lesen` (30 em шрифта чтения, примерно 55–60 букв) | лист лежит на ночном небе, картинка слева, текст обтекает |
| Игра | `.zug` → `.zk` `.zt1` `.zi` `.zr` | колонка: заголовок, задание, поле, гусеничка | то же, до `--mass-spiel` | две колонки: слева задание и гусеничка, справа поле во всю высоту |
| Доска | `.brett` | колонка | то же | слева карточки улик, справа вопросы и код |
| Окна | `.schl` + `.einst` / `.kgross` / `.brett.ueberl` | лист снизу | диалог по центру | диалог по центру |

Постраничное чтение (решение из `DECISIONS.md`) не менялось: разбивка по-прежнему в `blaetter()` в `main.ts`, запасная прокрутка листа при самом крупном шрифте сохранена.

## Как сделать новую игру или экран

1. Разметка игры — внутри стандартного каркаса `section.zug[data-art="имя"]` c детьми `.zk`, `.zt1`, `.zi`, `.zr`. Тогда телефон, планшет и альбомная раскладка работают сами.
2. Размеры — в `rem` и токенах (`var(--t-knopf)`, `var(--a-3)`, `var(--r-feld)`, `var(--sch-knopf)`). Шрифт не мельче `--t-etikett` (12 px). Всё нажимаемое — не меньше `--tipp` (44 px).
3. Главная картинка игры, которая определяет высоту: `width: min(100%, calc(var(--bild-h) * <ширина/высота>))`. `--bild-h` — свободная высота сцены. Если у игры под картинкой есть свои элементы (счётчик, переключатель, запас карточек), сообщить их высоту: `.zug[data-art="имя"] { --neben-spiel: 8rem; }`. Пример — `unterschiede` в `raetsel.css`.
4. Не использовать: `dvh`/`vh` в играх, фиксированные `px` для размеров, `!important`, префикс `#app` «чтобы победить», `width: max-content` без `max-width: 100%`.
5. Проверить (ниже).

## Проверка

```bash
cd app && npm run build
npm run test:ui                      # все экраны × 15 размеров, ~10 мин
node scripts/ui-audit.mjs --vp=360x620,768x1024 --nur=s05   # быстро: размеры и экраны по выбору
node scripts/ui-audit.mjs --zoom=1.3     # системный крупный шрифт Android
node scripts/ui-audit.mjs --insets=40,48 # системные панели сверху/снизу
node scripts/ui-audit.mjs --fs=26        # самый крупный шрифт «Aa»
```

Результат — в `03_screens/v8/audit/<имя>/`: `kurz.md` (короткий список уникальных проблем), обзорные листы `sheet_<размер>.png`, снимки каждого состояния. Картинки в Git не попадают, только `kurz.md`.

Что проверяется на каждом состоянии: выход за экран, перекрытые и недостижимые кнопки (проверка реальной точкой нажатия, без принудительных кликов), обрезанный и перекрытый текст, мелкие зоны нажатия и шрифт, искажённые картинки, лишняя прокрутка, системные поля. Состояния, до которых проверка не дошла, помечаются `NOT TESTED`.

## Что не проверено автоматически

- Реальный Android (WebView, жесты, вырезы экрана) — только браузерная эмуляция.
- Шаг с неверным ответом в играх `merkmale` (Spur 4) и `nest` (Spur 24).
